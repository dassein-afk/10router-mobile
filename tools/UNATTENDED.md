# 无人值守迭代防护规约（用户睡眠期）

用户授权：睡眠期间每 30 分钟自行迭代 UI + 截图，自行决断。
但立下硬闸，防止"无监督发坏包 / 误删功能 / 资源撑爆"。

## 1. 自动环路
- cron：`*/30 * * * * python3 tools/iter_engine.py >> tools/iter_cron.log 2>&1`
- 每轮：加载 UI → 5 项量化检查 → 从 iter_state.json 痛点队列挑一个 → 改 JS/HTML/CSS（热补丁，无需重装）→ 推补丁通道 → 写轮次日志。
- 视觉截图轮：由交互轮（我手动）跑 browser_exec 截 320/360/390，存 tools/iter_shots/，供用户醒后复核。

## 2. 硬闸（cron 轮绝不跨越）
- ⛔ 绝不发布 APK：检测到 Java/壳未提交改动（apk_rebuild_pending）时，只构建暂存 dist/，标记 awaiting_user，不碰 release/入口/落地页。
- ⛔ 绝不降级：下载入口永远指向最新、已验证版本；旧版只在"备用直连"历史列表，主按钮不变。
- ⛔ 绝不删功能无替代：删按钮/开关前必须在 state 记"删因+替代"，且保留可回滚 diff。
- ⛔ 不伪造证据：所有结论来自浏览器实测 / 构建 sha / 真机诊断，不编数据。

## 3. 中断防护（用户可能睡眠中突然发消息）
- 用户发"停/别动/退出"→ 立刻 `crontab -l | grep -v iter_engine | crontab -` 停环路，回"已停"。
- 用户发新需求 → 当前 cron 轮是独立进程，互不打架；我读消息后优先响应用户，环路下一轮自然按新 state 走。
- 用户醒后第一句多半是"你期间干了啥/有没有发坏包/各机型保活数据"→ 答案在 iter_state.json 的 rounds_log + awaiting_user，全可复核。

## 4. 预决事项（睡眠期我自行拍板，不等确认）
- 补丁通道 js/css 热更：随时可发（可逆、不重装、用户 App 下次打开即生效）。
- UI 文案/布局微调：以"横向不溢出 + 形态即性质 + 不降可读性"为红线，自行改。
- 设置页密度：低价值开关可合并/隐藏，但必须留"展开高级"入口，不彻底删。
- 回归门禁：每轮 5 项检查全 OK 才推补丁；任一失败则回滚该轮改动并记 fail。

## 5. 资源护栏
- 日志 >200KB 自动截断尾部 500 行。
- 截图每轮覆盖旧档（不无限累积）。
- 不并发构建（cron 30 分钟间隔远大于单次构建耗时）。

## 6. 用户醒后可一键回溯
- 所有改动有 git commit；`git log --oneline` 即时间线。
- 任意轮可 `git revert <hash>` 回到该轮前。
- 待发版项集中在 iter_state.json 的 awaiting_user，醒后一眼可见。
